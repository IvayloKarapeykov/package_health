The API is what the web app uses. It's plain JSON over HTTPS, with no account and no API key of its
own.

```text title="Base URL"
https://api.vet.ivaylokarapeykov.com
```

## Endpoints

| Method and path | Returns |
| --- | --- |
| `POST /api/analyze` | The full report as JSON, once it's done. See [Analyze](/docs/api-analyze) |
| `POST /api/analyze/stream` | Progress as Server-Sent Events, then the report. See [Streaming](/docs/api-stream) |
| `GET /api/ecosystems` | Every supported ecosystem and its dependency files |
| `GET /api/health` | Whether the server is up, and which of its own keys it has |

Interactive docs, with every field and a way to try requests, are at
[`/docs`](https://api.vet.ivaylokarapeykov.com/docs) on the API.

## Your keys

Send your own keys as headers. Both are optional, and they're used for that request only.

| Header | Effect |
| --- | --- |
| `X-GitHub-Token` | Your own 5,000 GitHub requests an hour instead of a shared 60 |
| `X-OpenRouter-Key` | Verdicts from Jev and reasons written by an LLM, billed to you |

## Request IDs

Every response has an `X-Request-ID` header. Send your own (letters, digits, `.`, `_` or `-`, up to
64 characters) and it's kept, so your logs and ours line up. Quote it when you report a problem.

## Errors

| Status | When |
| --- | --- |
| `422` with a message | The input can't be checked, like an invalid package name or an unreadable file |
| `422` with a list | The request body doesn't match either shape |
| `500` | Something failed on our side. Quote the request ID |

```json title="422"
{ "detail": "'guava' is not a valid Maven Central package name." }
```

A data source that's down doesn't fail the request. The report notes it on the packages it affects.
