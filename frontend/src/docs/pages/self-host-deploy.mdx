The public site runs the backend on Railway and the frontend on Vercel. The repo has the config for
both, so either works with a few settings. Any host that runs a Python web server and serves static
files will work too.

## Backend on Railway

<Steps>

### Create a service from the repo

In Railway, choose **Deploy from GitHub repo** and pick your fork.

### Point it at the backend

In the service's **Settings**, set **Root Directory** to `/backend` and **Railway Config File** to
`/backend/railway.json`. That file sets the start command and a health check on `/api/health`.

### Add the variables

```bash title="Variables"
CORS_ORIGINS=["https://your-frontend.example.com"]
MCP_ALLOWED_HOSTS=["api.example.com", "your-service.up.railway.app"]
LOG_FORMAT=json
LANGSMITH_TRACING=false
```

### Give it a domain

Under **Networking**, generate a Railway domain, or add your own with a `CNAME` record pointing at
the target Railway shows.

</Steps>

## Frontend on Vercel

<Steps>

### Import the repo

In Vercel, import your fork and set **Root Directory** to `frontend`. Vercel detects Vite.

### Set the API address

```bash title="Environment variable"
VITE_API_BASE_URL=https://api.example.com
```

### Add your domain

`frontend/vercel.json` already serves the app for every path, so links like `/docs` work on
reload.

</Steps>

## Checklist

- `OPENROUTER_API_KEY` and `GITHUB_TOKEN` are empty, so visitors use their own keys
- `CORS_ORIGINS` has the frontend's exact address
- `MCP_ALLOWED_HOSTS` has every domain the backend answers on
- `LANGSMITH_TRACING` is off, so visitors' searches aren't sent to your LangSmith account
